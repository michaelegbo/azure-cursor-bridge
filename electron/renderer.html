How to create one (free, about 5 minutes)
  1. In the Cloudflare dashboard open Zero Trust → Networks → Tunnels and choose Create a tunnel → Cloudflared.
  2. Name it, then copy the install command shown for any operating system. You can paste the whole command below; the bridge picks out the token.
  3. Under Public hostname, add a hostname on a domain you manage in Cloudflare (for example bridge.example.com), service type HTTP, URL localhost:17834.

A new hostname or token reconnects the public URL, which interrupts requests in flight through it. The token is stored encrypted with your operating system's keystore.

Bloat remover

Cursor and Codex resend the whole conversation on every turn, and most of it is old tool output: file dumps, logs, repeated reads. The bloat remover trims what is older before it goes upstream, so requests use fewer tokens. It never touches the system prompt, the tool definitions or your newest turns, and if anything goes wrong the request simply goes through untrimmed.

Higher levels save more tokens, but the model may lose details from earlier in the conversation. Each request's breakdown on the Requests page shows how much was removed. Summaries count as normal requests (client “Bloat remover”).

    Claude CLI models — names & effort
    
These models run through the local Claude Code CLI on your Claude subscription. Use them from any client exactly like the Azure models — same base URL, same bridge key. The bridge- prefix avoids clashing with clients' own built-in Claude model names (Cursor intercepts bare claude-* names). Model names:

    
    
     
  1. bridge-claude-fable — Claude Fable 5.1 (most capable)
    2. 
     
  2. bridge-claude-opus — Claude Opus 5.5 through the local Claude CLI (azure-opus remains the separate Azure Opus 5 deployment)
    3. 
     
  3. bridge-claude-sonnet — Claude Sonnet 5
    4. 
     
  4. bridge-claude-haiku — Claude Haiku 4.5 (fastest)
    5. 
    

    
Effort works like every bridge model — suffix the name (bridge-claude-opus-max, bridge-claude-haiku-low), send a client reasoning setting, or rely on the model card default. Opus 5.5 uses adaptive thinking at every effort level; low / medium / high / xhigh / max control its depth. Other Claude CLI models use thinking-token budgets: low = thinking off, medium = 4,096, high = 16,384, xhigh = 32,768, max = 63,999.

    
Tool calling: client tools (Cursor agent mode, Codex) work via emulation — the bridge passes the client's tool schemas to Claude in the system prompt with a strict call format, converts Claude's calls into standard OpenAI tool_calls, and feeds results back on the next request. One tool call per reply; Claude Code's own local tools are always disabled for bridge requests.

    
Requirements & limits: the Claude CLI must be installed and logged in on the bridge machine (Overview → Claude account). Usage draws on the subscription of the account marked In use there, including requests made with guest keys.

    
Switching accounts: Overview → Claude account lists every saved Claude account with its email, organization and plan. “Add another Claude account” signs a new one in (for example a personal plan next to your Team plan) without touching Claude Code's own login; Use switches the bridge to it from the next request, no restart needed.

    Fast mode (priority processing)
    
Fast mode sends a request to Azure's priority processing tier (OpenAI calls it "fast mode"): lower latency and higher output speed, billed at a higher rate. On Azure it is currently offered for GPT-6 Sol (azure-sol) on Global or US Data Zone standard deployments — not for GPT-6 Astra, and not for the Claude models.

    
    
     
  1. App toggle — Overview → the model's card → Fast mode (saves immediately). Applies to every request for that model.
    2. 
     
  2. Client setting — a client that sends its own service_tier wins over the toggle: fast or priority turns fast mode on for that request, default turns it off (Codex's fast toggle uses this). flex and auto are ignored because Azure rejects flex for these models.
    3. 
    

    
Azure may quietly serve a fast request at standard speed (and standard price) if traffic ramps up more than 50% within 15 minutes or during peak load. The Requests page shows what actually happened: ⚡ fast or fast requested, Azure served standard. Cost estimates apply the Fast mode × multiplier from Usage & cost only to tokens Azure really served fast. Fast mode uses the same TPM quota as standard.

   

   

    Control reasoning effort
    
The Azure models support five reasoning levels: low, medium, high, xhigh and max. Higher levels think longer and use more output tokens. There are three ways to choose, and the most specific one wins:

    
    
     
  1. Effort in the model name (strongest) — pick a suffixed model such as azure-astra-low, azure-sol-max or azure-opus-high. This is how you control effort from Cursor's model picker. Works from any OpenAI-compatible client.
    2. 
     
  2. The client's own reasoning setting — Codex has a native effort selector next to the model name and sends your choice with every request; the bridge honors it. API callers can send reasoning_effort (chat) or reasoning.effort (responses).
    3. 
     
  3. The bridge default (weakest) — the Reasoning mode dropdowns above apply when a bare model name is used and the client sends no preference. This is what Cursor's bare azure-astra uses.
    4. 
    

    
Every request's resolved effort is shown in Recent requests below, so you can confirm which level actually ran.

    Azure upstream key & versions
    
The bridge authenticates to Azure with the key shown under “Azure upstream key”. Keys are stored DPAPI-encrypted per version in the bridge state folder; nothing is kept in plain text. Reveal decrypts and shows a key, Test against Azure sends one tiny real request (a few tokens) to confirm Azure accepts it, Save as new version stores a pasted key as the next version and activates it, and Activate on an older version reverts to it. Activation rewrites the key file and restarts the proxy, so the change applies to the next request. The active version can never be deleted.

   

   

    Cost estimation
    
The bridge records exact token usage (input, cached input, output) for every request into daily totals, and multiplies them by the rates you save under “Usage & cost”. Cost per request = fresh input × input rate + cached input × cached rate + output × output rate (rates are per 1 million tokens). Azure serves repeated prompt prefixes from its cache at a lower rate, which is why cached input is priced separately — enter the cached rate from your Azure pricing page, or the full input rate if you prefer a conservative estimate. Once rates are saved, each row in Recent requests also shows its estimated cost. These figures are estimates based on the rates you entered; your Azure invoice is authoritative.

   

   

    Guest keys & owner key rotation
    
The owner key is stored in the bridge config and never changes on its own — it is permanent until you press Rotate in “API keys & access”. Rotating invalidates the old value on the next request and copies the new one to the clipboard; afterwards paste it into Cursor (as the OpenAI API key) and update the AZURE_CURSOR_BRIDGE_API_KEY environment variable for Codex.

    
Guest keys are additional keys for the same endpoint with limits you control: an optional expiry set at creation, an on/off switch, Reset (new value, old one dies instantly), and Delete. The proxy re-checks keys on every request, so all changes are immediate — no restart needed. Each request in Recent requests shows which key authenticated it, with a per-key request counter in the table above.

   

   

    Bloat remover — trimming long conversations
    
Settings → Bloat remover trims what Cursor and Codex resend on every turn before it goes upstream. Small only tidies older tool output (colour codes, blank and repeated lines, exact duplicates). Medium, High and Aggressive shorten tool results, replies and pasted text that are older than the last 6, 4 or 3 turns, keeping the start and end of each. Deep also has a model you choose summarize the early conversation, 6 turns at a time; each block is summarized once and cached, so later requests reuse it.

    
The system prompt, tool definitions and newest turns are never changed, and no tool call is separated from its result. Shortening older messages only changes the part of the prompt that was already old, so Azure's prompt cache keeps working for the rest. Each request's breakdown shows what was removed. If anything fails, the request goes through untrimmed.

   

   

    How the endpoint works
    
The bridge runs locally (port 17834 by default, changeable in Settings) and translates OpenAI-style requests to your Azure deployments, your Claude subscription (Claude CLI) or your ChatGPT plan (Codex CLI). Cloudflare publishes it on the internet for Cursor: with your own Cloudflare tunnel at a permanent hostname, otherwise at a temporary trycloudflare URL that changes on every start. Choose between them, or turn the public URL off, in Settings → Public URL. The tunnel token is stored encrypted with the OS keystore.

    
All data stays in one local SQLite database. Settings → Local database shows where it is, how much history is kept, and lets you clear any part of it or reset it to defaults.

Rate-limit queue

   
Models with a tokens-per-minute budget never fail on it: a request that doesn't fit waits until it does, while smaller requests that fit go straight in. After waiting 10 seconds, the oldest request gets priority, so nothing starves. If Azure itself throttles, the model's queue pauses for the time Azure asks. Models without a budget skip the queue entirely.
